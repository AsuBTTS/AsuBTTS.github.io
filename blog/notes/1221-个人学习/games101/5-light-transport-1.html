5-Light Transport 1

1. Shadow Mapping

一种基于图像空间（image-space）的阴影算法。它在计算阴影时不直接处理场景几何，而是利用“从光源看过去的深度图”判断某点是否被遮挡。核心思想是：一个点若不在阴影中，它必须同时能被相机看见，也能被光源看见。

1.1 基本流程

1.1.1 从光源视角渲染

先以光源为“相机”渲染场景，只记录深度，得到一张 shadow map。这张图保存了从光源出发，每个方向上最先看到的表面深度。

1.1.2 从相机视角正常渲染

再从眼睛视角渲染场景，得到当前屏幕上可见的点。

1.1.3 把当前可见点投影回光源空间

对于相机看到的每个着色点，把它重新投影到光源坐标系中，得到它在 shadow map 上的位置，并比较：

  • 若该点到光源的深度 与 shadow map 记录的深度一致，说明它就是光源看到的最前面的点，可见，不在阴影中
  • 若该点深度 更大，说明它前面还有别的物体挡住了光，在阴影中

1.2 直观理解

shadow map 本质上是在问：
“从光源方向看，这里最先撞到的是不是你这个点？”

  • 是你：说明没被挡住
  • 不是你：说明前面有遮挡物，你就在阴影里。

1.3 优点与问题

优点

  • 思路直接，适合和光栅化管线结合
  • 是很经典、很常用的实时阴影方法，早期动画和几乎所有 3D 游戏都大量使用。
    问题
  • 只能天然得到 硬阴影
  • 效果强烈依赖 shadow map 分辨率，容易出现锯齿、走样
  • 深度比较是浮点数比较，容易出现 shadow acne / bias / tolerance 一类问题。

2. Whitted-Style Ray Tracing


Whitted-Style Ray Tracing 是经典递归光线追踪模型。它的目标是比光栅化更自然地处理：

  • 阴影
  • 镜面反射
  • 折射
  • 一部分全局光照效果。

相比 rasterization，它更擅长处理“光会继续传播和反弹”的现象，但代价是计算很慢。

2.1 Assumption of Light Transport Model

Whitted 风格的基础想法可以概括成几条：

  • 光沿直线传播
    在几何光学近似下，把光视为沿直线前进。这样就可以用一条 ray 去描述光的路径。

  • 光线可逆
    真实物理上常说光从光源到眼睛，但由于 路径可逆（reciprocity），在渲染里我们通常从相机往场景发射光线，这样更高效，因为只有最后进入眼睛的光才和成像有关。

  • 光线之间互不影响
    在基础模型中默认不同光线彼此独立，不考虑它们互相碰撞之类的复杂波动效应。

  • 基本 Ray Casting(光线投射) 思想
    最初的 ray casting 只做两件事：

  1. 每个像素发一条主光线
  2. 从交点向光源发阴影光线判断是否被遮挡。

Whitted 在此基础上继续加入反射光线和折射光线，于是形成光线追踪的递归结构。
在计算之后返回RGB三元组，进一步交给渲染

2.2 Ray Tracing基本过程

相关函数算法可以参考GAMES101参考资料

2.2.1 主光线（primary ray）

从眼睛穿过像素发出一条光线，找到它与场景中最近的交点。

2.2.2 在交点处做局部着色

先计算直接光照，比如漫反射、高光等局部项。

2.2.3 发射次级光线（secondary rays）

如果材质具有镜面反射或折射性质，就继续生成：

  • 反射光线：沿镜面反射方向继续追踪
  • 折射光线：沿透射方向继续追踪
  • 阴影光线：朝向光源，检测遮挡。

2.2.4 递归累加结果


次级光线再与物体相交，又会生成新的次级光线，于是形成递归树。最终像素颜色由：

  • 本点直接着色
  • 反射返回的颜色
  • 折射返回的颜色
  • 阴影可见性
    共同决定。

2.4 优缺点

Whitted 风格特别适合：

  • 理想镜面反射
  • 理想折射
  • 清晰阴影
  • 直接光照下的高光。

它并不是真正完整的全局光照解。后面课程专门指出它的问题：

  • 对 glossy reflection 不自然，因为不是单一反射方向
  • 对 diffuse-diffuse 之间的间接反弹处理不好
    所以它是经典模型，但并不等价于完整的 rendering equation 解。

3. Accelerating Ray-Surface Intersection

光线追踪最贵的地方之一，是 求光线和场景几何的交点。

如果每条 ray 都去和场景里每个三角形测试一次，复杂度大致就是：

像素数 × 物体数 × 反弹次数

场景一大就会非常慢。课程里直接指出，朴素做法需要对每条 ray 穷举测试所有三角形。

所以必须做加速结构。

3.1 Bounding Volumes

基本想法：
先用一个简单体积把复杂物体包起来，先测 ray 是否打到这个包围体。

  • 若连包围体都没打中，那肯定不可能打中里面的真实物体
  • 若打中了包围体，再去测真实几何。
    最常见的是 AABB（Axis-Aligned Bounding Box，轴对齐包围盒），也就是盒子的边和 x/y/z 轴平行。这样求交会更简单。

    Ray-AABB 相交思想

一个盒子可以看成 3 对 slab（平行平面夹出的区间）的交。

对每个轴分别算 ray 进入和离开该 slab 的参数区间：

  • 得到每个轴上的 tmin 和 tmax
  • 总进入时刻 t_enter = max(各轴 tmin)
  • 总离开时刻 t_exit = min(各轴 tmax)
    若：
  • t_enter < t_exit
  • 且 t_exit >= 0
    ->则 ray 与 AABB 相交。

AABB 的好处就是：
和一般平面求交相比，轴对齐后每个 slab 只需要很少的减法和除法，代价小很多。

3.2 Uniform Spatial Partitions (Grids)

3.2.1 基本过程

Uniform Grid 就是把整个场景包围盒切成很多规则小格子。预处理时：

  1. 找场景 bounding box
  2. 建立网格 create grid
  3. 把每个物体登记到所有它覆盖的格子Store each object in overlapping cells

    追踪 ray 时，按 ray 穿过网格的顺序逐格前进：
  • 每到一个格子，只测试这个格子里登记的物体
  • 而不是测试整个场景。
3.2.2 问题和局限

对于Grid Resolution, 网格不是越细越好。

  • 太粗：比如只有一个格子(One Cell)，等于完全没加速
  • 太细：Too many Cells 会花很多时间在穿格子上，额外遍历开销很大。

GAMES101课程里给了一个经验启发：
3D 中可令 cell 数 ≈ 27 × object 数 作为启发式。

总的来讲Uniform Grid适合：

  • 物体很多
  • 大小比较接近
  • 空间分布比较均匀。

典型失败例子是 “teapot in a stadium”：

  • 一个很小的精细物体
  • 放在一个特别大的空场景里
    这时统一网格很难同时兼顾大尺度空区域和小尺度细节。

3.3 Spatial Partitions

3.3.1 Oct-Tree

Oct-Tree 是一种递归空间划分：
每次把一个 3D 空间盒子继续切成 8 个子盒子。
特点：

  • 比 uniform grid 更自适应
  • 稀疏区域不会被切得过密
  • 适合层次化管理空间。
3.3.2 KD-Tree


KD-Tree 也是空间划分结构，但每次不是切成 8 份，而是用一个与坐标轴平行的平面，把空间二分。

3.3.2.1 结构

内部节点存：

  • 划分轴（x / y / z）
  • 划分位置
  • 左右子节点指针
    叶节点存：
  • 该区域内的物体注册列表。
3.3.2.2 追踪过程：Traversing a KD-Tree
  • 看光线先进入哪个子空间，先遍历近处子节点
  • 若近处子节点找到交点，再用 t_hit 判断是否还需要去远处子节点。
  1. 从根节点开始，先判断光线是否进入整个包围盒
  2. 到达一个节点时，先区分它是不是叶节点
  3. 对内部节点，先求光线与分割平面的交点参数
  4. 根据光线方向和起点位置，确定 near child 和 far child
  5. 根据 与当前区间 的关系决定递归方式
    若 ，说明在当前有效区间内，光线已经位于 far child 一侧，所以只需递归 far child。
    若 ，说明在当前有效区间内，光线始终位于 near child 一侧，所以只需递归 near child。

KD-Tree 的本质是：
划分的是空间本身，所以一个物体可能跨越多个区域，被存进多个地方。

3.3.3 BSP-Tree

BSP-Tree（Binary Space Partitioning）和 KD-Tree 很像，也是在递归地用平面切空间。区别在于：

  • KD-Tree 通常限制切分平面与坐标轴对齐
  • BSP-Tree 的切分平面可以更一般、更自由

3.4 Object Partitions & Bounding Volume Hierarchy (BVH)

BVH 是另一种思路，不再直接切空间，而是划分物体集合。

也就是说：

  • 把场景中的物体递归分成两个子集
  • 给每个子集包一个 bounding box
  • 继续对子集递归。:contentReference[oaicite:40]{index=40}


3.4.1 BVH 的构建

  1. 求当前物体集合的 bounding box
  2. 把物体集合递归分成两个子集
    划分思路：
    Heuristic #1: Always choose the longest axis in node
    Heuristic #2: Split node at location of median object
  3. 重新计算两个子集的 bounding box
  4. 满足终止条件后停止
  5. 在叶节点保存物体列表。

3.4.2 BVH数据结构

内部节点Internal nodes存：

  • bounding box
  • 两个子节点指针
    叶节点存：
  • bounding box
  • List of objects

3.4.3 BVH 遍历


遍历时：

  1. 先测 ray 是否打中当前节点 bbox
  2. 若没打中，整棵子树直接跳过
  3. 若是叶节点，就测试叶子中的物体
  4. 若是内部节点，就递归遍历两个子节点
  5. 返回最近交点。
