1-图形学API与shader语言

1. 从 CPU 到 GPU 的总览过程

一次基本的实时渲染，可以先看成这样一条链：

  1. CPU 准备场景数据
  2. CPU 通过图形学 API 把数据和命令提交给 GPU
  3. GPU 执行图形管线
  4. Vertex Shader 处理顶点
  5. 光栅化生成片元
  6. Fragment Shader 处理片元
  7. 结果写入 framebuffer
  8. 最终显示到屏幕上

也就是：

CPU 组织数据 → API 提交资源与命令 → GPU 执行 Shader 与光栅化 → 输出图像

1.1 CPU 准备数据

得到什么：

  • 顶点位置
  • 法线
  • 纹理坐标
  • 索引
  • 纹理图片
  • 变换矩阵
  • 光源参数
  • 相机参数

用什么：

  • 应用程序代码
  • 模型资源
  • 图片资源
  • 数学计算结果

做什么：

CPU 先把“要画什么”描述清楚，也就是完成场景组织和数据准备。

1.2 通过图形学 API 把数据交给 GPU

得到什么：

  • buffer
  • texture
  • uniform
  • shader program

用什么：

  • OpenGL
  • WebGL
  • DirectX
  • Vulkan
  • Metal
  • WebGPU

做什么：

把 CPU 侧的数据上传到 GPU，并配置渲染流程。

其中最常见的几类资源是：

  • buffer：存顶点、索引等结构化数据
  • texture：存可按坐标访问的数据，如颜色、深度、法线
  • uniform：存一次 draw call 共享的参数
  • shader program：GPU 要执行的着色器程序

1.3 GPU 开始执行图形管线

得到什么：

  • 顶点数据
  • 索引数据
  • 纹理资源
  • uniform 参数
  • shader 程序

用什么：

  • Vertex Shader
  • 光栅化
  • Fragment Shader

做什么：

GPU 按照 draw call 的要求，把几何数据逐步变成屏幕上的像素结果。

1.4 Vertex Shader 处理顶点

得到什么：

  • 每个顶点的 position、normal、uv、color
  • 整批共享的 uniform，如 M、V、P 矩阵

用什么：

  • attribute
  • uniform

做什么：

  1. 计算顶点最终位置
  2. 输出后续阶段还需要的数据

典型形式：

gl_Position = P * V * M * vec4(aPosition, 1.0);

这一步得到的是顶点在裁剪空间中的位置，同时还会输出法线、纹理坐标、世界坐标等信息，供后续插值使用。

1.5 光栅化

得到什么：

  • 三角形覆盖到哪些屏幕区域
  • 会生成哪些片元
  • 每个片元对应的插值属性

用什么：

  • 顶点着色器输出的位置
  • 顶点着色器输出的 varying 数据

做什么：

把三角形离散化成片元，并对顶点输出的数据自动插值，得到每个片元对应的法线、uv、颜色、坐标等信息。

1.6 Fragment Shader 处理片元

得到什么：

  • 插值后的法线
  • 插值后的纹理坐标
  • 插值后的世界坐标
  • uniform 中的光源、材质参数
  • texture 中采样出的值

用什么：

  • varying
  • uniform
  • texture

做什么：

计算这个片元最终输出什么颜色。

例如：

  • 采样纹理
  • 计算光照
  • 混合环境光、漫反射、高光
  • 输出最终颜色

典型形式：

gl_FragColor = texture2D(uTexture, vUV);

或

gl_FragColor = vec4(finalColor, 1.0);

1.7 写入 framebuffer 并显示到屏幕

得到什么：

  • 通过测试的片元颜色
  • 深度结果
  • 最终图像缓冲内容

用什么：

  • 深度测试
  • 模板测试
  • 混合
  • framebuffer

做什么：

把通过测试的片元结果写入 framebuffer，最终显示到屏幕上。

2. Shader 和 Shader Language

2.1 Shader 是什么

Shader 是运行在 GPU 上的小程序。
它不是完整应用，而是图形管线某个阶段的计算规则。

常见类型包括：

  • Vertex Shader
  • Fragment Shader
  • Geometry Shader
  • Tessellation Shader
  • Compute Shader

基础实时渲染里最核心的是：

  • 顶点着色器
  • 片元着色器

2.2 顶点着色器做什么

顶点着色器处理单个顶点的数据，例如：

  • position
  • normal
  • uv
  • color

它的主要任务是：

  1. 把顶点变换到裁剪空间
  2. 输出后续需要插值传递的数据

最关键的输出是：

  • gl_Position

典型形式：

gl_Position = P * V * M * vec4(aVertexPosition, 1.0);

这里完成的是：

局部空间 → 世界空间 → 观察空间 → 裁剪空间

2.3 片元着色器做什么

片元着色器处理光栅化后生成的片元。
它决定这个片元最终输出什么颜色。

常用输入包括：

  • 插值后的法线
  • 插值后的坐标
  • 插值后的纹理坐标
  • 纹理采样结果
  • 光源参数
  • 材质参数

基础形式通常是：

gl_FragColor = vec4(color, 1.0);

2.4 Shader 语言是什么

Shader 语言就是用来编写 GPU 着色器程序的语言。

常见的 Shader 语言有：

  • GLSL：OpenGL / WebGL 常用
  • HLSL：DirectX 常用
  • MSL：Metal 常用
  • WGSL：WebGPU 常用

你目前最常接触的是 GLSL。

2.5 GLSL 的几个常见变量类型

（1）attribute

表示每个顶点独有的输入属性，例如：

  • 顶点位置
  • 法线
  • UV

例如：

attribute vec3 aVertexPosition;

它来自顶点缓冲，对每个顶点分别提供。

（2）uniform

表示一次 draw call 中共享的参数，例如：

  • 变换矩阵
  • 光源位置
  • 材质参数
  • 时间
  • 相机位置

例如：

uniform mat4 uProjectionMatrix;

它对一批顶点或片元共同生效，不会在图元内部插值。

（3）varying

用于顶点着色器输出、片元着色器输入的数据传递。
它会在光栅化阶段自动插值。

例如：

varying vec3 vNormal;

流程是：

  1. 顶点着色器输出 vNormal
  2. 光栅化阶段对三角形内部插值
  3. 片元着色器接收当前片元对应的插值结果

2.6 一个最小的 Shader 例子

顶点着色器

attribute vec3 aVertexPosition;
uniform mat4 uModelViewMatrix;
uniform mat4 uProjectionMatrix;

void main(void) {
    gl_Position = uProjectionMatrix * uModelViewMatrix * vec4(aVertexPosition, 1.0);
}

作用：

  • 读取顶点位置
  • 进行变换
  • 输出到 gl_Position

片元着色器

#ifdef GL_ES
precision mediump float;
#endif

void main(void) {
    gl_FragColor = vec4(1.0, 1.0, 1.0, 1.0);
}

作用：

  • 给每个片元输出纯白色

2.7 Shader 与固定管线的区别

早期图形 API 中，许多流程是固定的，例如固定光照、固定纹理流程、固定变换方式。

可编程管线出现后，我们可以自己写 Shader，决定：

  • 顶点怎么变换
  • 法线怎么处理
  • 光照怎么算
  • 颜色怎么混合
  • 阴影怎么做

现代图形学的重要变化之一，就是从固定功能管线转向可编程管线。

2.8 为什么 Shader 很重要

现代实时图形中的大量效果都依赖 Shader，例如：

  • Phong 光照
  • 法线贴图
  • 阴影映射
  • PBR
  • 屏幕后处理
  • NPR
  • 水体、火焰、描边、粒子效果

2.9 API 与 Shader 的关系

可以简单记成：

图形学 API 决定资源和流程怎么组织，Shader 决定图形管线中的局部计算怎么发生。
