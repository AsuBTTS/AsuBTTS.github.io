2-实时阴影算法

1. Basic Shadow Mapping

1.1 shadow map 基本思路

在Phong Shading模型中，只是对于物体处理了diffuse, specular 以及 ambient 的情况，是对是对各项局部光照分量的加和，并没能处理因物体间的遮挡关系而产生的阴影。

Shadow Mapping 是一个非常直观的算法，对于当前着色点，我们将其变换到光源视角下得到对应深度，并与 shadow map 中记录的最近深度进行比较，从而判断该点是否被遮挡，得到可见度(visibility)信息，再进行渲染。

我们在渲染之前，会预先在光源的视角下经过坐标变换得到在光源视角下的"屏幕"，得一张坐标范围为 的、一系列离散坐标 作为索引的表——Shadow Map，这张表存储着从光源出发打到的最近的场景点的深度。
与 texture 类似，我们也把shadow map上的一个个格子叫做"texel"。

在渲染时，我们从camera的视角出发，对于当前pixel打到的场景点p，我们把p的深度通过矩阵变换为光源视角下的深度 （不严谨地：物理直观上理解就是到达光源的距离）与当前点shadow map 的 texel上存储的深度 （物理直观上就是这个方向上，shadow map记录的最小距离）做比较。
如果 ，便说明这一处有更近的物体遮挡光源，那么此处便应当是阴影。如果在精度允许的范围内 那么说明这一点能被光源照射到。（注意，必须强调精度允许范围，因为变换会损失精度，浮点数比较也应当注意精度问题）

最后我们返回一个二值(0/1)变量 visibility 来说明是否可见。（在后续 PCF 等方法中，visibility 常会变成 之间的连续值。）

这个思路是直观的，天然适合处理点光源这类理想无面积光源所产生的硬阴影，也常用于其他单光源的直接阴影计算中。正如我们在5-Light Transport 1中提到的那样。

1.2 自遮挡问题与优化

这个算法看起来优雅，但是在实际操作过程中会遇到一个严重的问题：self-occlusion 现象（自遮挡）。

如图，左为自遮挡产生的诡异纹路，右为shadow detached现象

[Image from RTR4]

因为对于 shadow map 的一个 texel 而言，其覆盖一定的空间区域，对于在一区域中相近的两点 p, q 的情况，p 是相机视角下的着色点，经过深度变换得到了光源视角下的深度 。在该区域对应的texel上记录的对应的深度信息，是另一个临近点 q 的，这个 q 的深度会小于 p，这就导致我们会把p误判成阴影。

为什么是误判呢？因为 p, q 很近，在物理空间上两点共处一个表面，理论上可见性应该是一样的，但是却因为 texel 离散化带来的精度问题（一个 texel 覆盖一片区域，里面很多连续点被压成一个深度值）导致了误判，就好像我自己遮挡了我自己，因此我们称之为自遮挡。

1.3 glsl 代码示例

float useShadowMap(sampler2D shadowMap, vec4 shadowCoord){
  vec3 projCoords = shadowCoord.xyz / shadowCoord.w;//着色点p的深度
  projCoords = projCoords * 0.5 + 0.5;              //得到NDC

  //边缘判断
  if(projCoords.x < 0.0 || projCoords.x > 1.0 ||
     projCoords.y < 0.0 || projCoords.y > 1.0 ||
     projCoords.z < 0.0 || projCoords.z > 1.0) {
    return 1.0;
  }

  //得到用于比较的两个深度信息
  float currentDepth = projCoords.z; 
  float closestDepth = unpack(texture2D(shadowMap, projCoords.xy));

  //计算bias
  vec3 normal = normalize(vNormal);                 //vNormal是varying
  vec3 lightDir = normalize(uLightPos - vFragPos);  //这两个是uniform
  float bias = max(0.006 * (1.0 - dot(normal, lightDir)), 0.0005);

  //判断并返回visibility 二值
  return currentDepth > closestDepth + bias ? 0.0 : 1.0;
}

2. PCF算法

2.1 基础shadow mapping的问题

基础 shadow mapping 算法很直观，但问题很明显，得到的阴影硬且脏，边缘生硬（我们称之为 hard shadow, 硬阴影），并且容易出现明显的锯齿与块状感。

硬阴影（左）与软阴影（右）

[RenderMan]

在一个真实的世界中，我们见到的阴影边缘通常不是 shadow mapping 那样的硬阴影（这只会在少数情况下发生）。真实阴影边缘区域存在由深到浅的过渡，即软阴影（Soft Shadow）。因此我们需要进一步优化 Shadow Mapping 来实现软阴影。

在之前的模型中，我们对于当前着色点，要么认为它完全处于阴影中，要么认为它完全可见——这种“非黑即白”的判断方式，与 shadow map 本身的离散 texel 结构叠加起来，会使阴影边界显得更加生硬，并产生明显锯齿。

2.2 算法基本思路

怎么解决呢？一个思路是不再“非黑即白”，承认世界存在“灰色地带”。也就是说，我们认为边缘的点并不是完全不可见，也不是完全可见。

基于这样的思维，我们就不能简单认为 visbility 是一个二值函数，完全可以把它当作是在0~1之间的任意百分比的值。这样阴影边缘的点的可见性便会有类似100%, 90%, 50%, 20%, 5%, 0%这样的变化，便可以得到渐变的灰度了。

PCF算法示意图，采样与权重

[GAMES202]

显然，我们可以进行采样与滤波来实现这一操作。也就是：对于当前着色点在 shadow map 上投影得到的位置，我们不仅比较其对应 texel 的深度，还会对其周围一定邻域内的 texel 一并做深度比较。最终，我们能得到不同的01值的分布。在最直观的均匀加权情况下，可见样本数与总采样数的比值，就可以视为该位置的可见性估计。

不过，在更一般的滤波模型中，邻域内各采样点的权重未必相同；权重通常会与采样点到中心位置的距离有关。也就是说，我们在对邻域采样时，还要引入权重的处理。

对于当前Shadow采样点 p，邻域的一个点 q，定义一个权重函数 ，一个判断遮挡的二值函数 ，算法可以表达为如下卷积格式：更进一步地，对于场景的着色点 x，展开二值函数，最终的可见性可以表述为：

总结起来就是：

  1. 在 shadow map 上取一组邻域采样点；
  2. 对每个采样点分别做一次“ 是否大于该处深度”的比较；
  3. 将得到的一组 0/1 可见性结果做平均，或更一般地做加权平均。

因此这一算法被称作 Percentage Closer Filtering，简写为PCF。

需要注意的是，PCF 得到的“软化边界”本质上来自邻域采样结果的平均，是一种视觉上的平滑；它并没有真正根据面光源几何关系去计算半影宽度，因此模糊范围通常是固定的。

2.3 glsl 代码示例

PCF 区别于基础 shadow mapping 的关键就是 visibility 成了一个比例，因此主要增加的内容是采样和加权平均。

float PCF(sampler2D shadowMap, vec4 coords) {
  vec3 projCoords = coords.xyz / coords.w;
  projCoords = projCoords * 0.5 + 0.5;

  if(projCoords.x < 0.0 || projCoords.x > 1.0 ||
     projCoords.y < 0.0 || projCoords.y > 1.0 ||
     projCoords.z < 0.0 || projCoords.z > 1.0) {
    return 1.0;
  }

  float currentDepth = projCoords.z;

  vec3 normal = normalize(vNormal);
  vec3 lightDir = normalize(uLightPos - vFragPos);
  float bias = max(0.005 * (1.0 - dot(normal, lightDir)), 0.0005);
  
  // 生成当前采样点周围的一组泊松盘分布偏移，用于邻域采样
  poissonDiskSamples(projCoords.xy);

  float visibility = 0.0;
  float filterRadius = 0.002;

  for(int i = 0; i < PCF_NUM_SAMPLES; i++) {
    //在中心 uv 周围采样
    vec2 sampleUV = projCoords.xy + poissonDisk[i] * filterRadius;
    //这里用 `unpack` 是因为该实现将深度值编码存入纹理中，采样后需要先解码。
    float closestDepth = unpack(texture2D(shadowMap, sampleUV));
    //每个样本做一次深度比较
    if(currentDepth > closestDepth + bias) {
      visibility += 0.0;
    } else {
      visibility += 1.0;
    }
  }
  //这里只做了等权平均
  visibility /= float(PCF_NUM_SAMPLES);
  return visibility;
}

3. PCSS

3.1 PCF的局限性

PCF 的核心思路，是通过对 shadow map 邻域内多个采样点分别做深度比较，再将结果平均，来得到一个位于 0~1 之间的 visibility。这样做确实能够有效缓解基础 shadow mapping 所产生的锯齿与生硬边界问题。

但是，PCF 的“软化”本质上来自固定采样邻域上的平均，因此它的模糊范围通常是固定的。也就是说，无论遮挡物与接收面的距离关系如何变化，阴影边界的模糊宽度往往都差不多。

这与真实世界中的软阴影并不一致。对于面积光源来说，阴影边界的过渡宽度并不是一个固定值，而是会随着遮挡体、接收点与光源之间的空间关系变化。通常来说：

  • 接收点越远离遮挡物，半影区域越宽；
  • 接收点越靠近遮挡物，阴影边界越锐利。

也就是说，PCF并没有真正处理半影宽度随几何关系变化这一关系。

这就是 PCSS（Percentage Closer Soft Shadows） 要进一步解决的问题。

3.2 PCSS基本思想与做法

在开启算法思想的描述前，我们先要明确如下概念：

  • Blocker：遮挡物，挡住光源的物体
  • Umbra：本影，光源被完全挡住的区域
  • Penumbra：半影，光源被部分挡住的区域
  • Receiver：接收阴影的表面

因此关键在于，如何定义遮挡物，又该如何寻找/判定遮挡物。

在真实几何图像中，我们可以清楚地区分 blocker、receiver 与面积光源的位置关系；但在实际算法中，我们手里只有 shadow map 这张从光源视角记录下来的离散深度图。因此，“寻找遮挡物”这件事，本质上是在 shadow map 上对当前 receiver 前方可能存在的 blocker 做一个局部估计，也就是在当前 receiver 前方、当前局部区域内，对遮挡物深度做一个平均估计。

以上的流程我们称之为 Blocker Search。解决了blocker的定义与寻找的问题，我们就可以自然地给出PCSS的流程了：

  1. Blocker Search：在当前点附近搜索 blocker，并估计其平均深度。
  2. Penumbra Estimation：根据 blocker 深度与 receiver 深度，估计当前点的半影宽度，并据此确定 filter size。
  3. Percentage Closer Filtering：使用该 filter size 做一次自适应的 PCF。

float findBlocker( sampler2D shadowMap,  vec2 uv, float zReceiver ) {
  // findblocker判断也需要做bias矫正
  vec3 normal = normalize(vNormal);
  vec3 lightDir = normalize(uLightPos - vFragPos);
  float bias = max(0.003 * (1.0 - dot(normal, lightDir)), 0.0005);

  //同时我们需要建立一个泊松采样环
  poissonDiskSamples(uv);
  float searchRadius = 0.006;

  float blockerDepthSum = 0.0;
  int blockerCount = 0;

  for(int i = 0; i < BLOCKER_SEARCH_NUM_SAMPLES;i++){
    vec2 sampleUV = clamp(uv + poissonDisk[i] * searchRadius, 0.001, 0.999);
    float shadowDepth = unpack(texture2D(shadowMap, sampleUV));
      if(shadowDepth + bias < zReceiver) {
      blockerDepthSum += shadowDepth;
      blockerCount++;
    }
  }
    if(blockerCount == 0) {
    return -1.0;
  }

  return blockerDepthSum / float(blockerCount);
}

#define LIGHT_WIDTH 0.05

float PCSS(sampler2D shadowMap, vec4 coords){
  vec3 projCoords = coords.xyz / coords.w;
  projCoords = projCoords * 0.5 + 0.5;
  
  if(projCoords.x < 0.0 || projCoords.x > 1.0 ||
     projCoords.y < 0.0 || projCoords.y > 1.0 ||
     projCoords.z < 0.0 || projCoords.z > 1.0) {
    return 1.0;
  }

  float zReceiver = projCoords.z;

  // STEP 1: avgblocker depth
  float avgBlockerDepth = findBlocker(shadowMap,projCoords.xy,zReceiver);
  if(avgBlockerDepth < 0.0) {
    return 1.0;
  }
  
  // STEP 2: penumbra size
  float penumbra = (zReceiver - avgBlockerDepth) * LIGHT_WIDTH / avgBlockerDepth;
  
  // STEP 3: filtering
  poissonDiskSamples(projCoords.xy);
  float visibility = 0.0;
  float filterRadius = penumbra * 0.18;
  
  vec3 normal = normalize(vNormal);
  vec3 lightDir = normalize(uLightPos - vFragPos);
  float bias = max(0.0045 * (1.0 - dot(normal, lightDir)), 0.0007);

  for(int i = 0; i < PCF_NUM_SAMPLES; i++) {
    //在中心 uv 周围采样
    vec2 sampleUV = clamp(projCoords.xy + poissonDisk[i] * filterRadius, 0.001, 0.999);
    float closestDepth = unpack(texture2D(shadowMap, sampleUV));
    //每个样本做一次深度比较
    if(zReceiver > closestDepth + bias) {
      visibility += 0.0;
    } else {
      visibility += 1.0;
    }
  }
  visibility /= float(PCF_NUM_SAMPLES);
  return visibility;

}

需要注意的是，VSSM 用统计量近似替代了显式采样，虽然效率更高，但也会带来一定误差，典型问题包括 漏光（light leaking） 和 非平面性伪影（non-planarity artifact）。

关于漏光：切比雪夫不等式给出的只是一个上限，当实际深度分布与VSSM假设的“单峰、连续”分布不符时（例如，场景中有多个遮挡物，形成多峰分布），该估计会严重偏离实际值，导致低估遮挡概率，产生漏光。

关于非平面性伪影：VSSM 只记录了深度的均值和方差，丢失了深度变化的具体模式。当核覆盖了曲率较大的区域时，统计模型无法区分“这是同一个弯曲表面上的连续变化”还是“两个不同深度平面的遮挡关系”。结果就是，本应因曲率而产生连续自阴影的区域，VSSM 错误地认为其中一部分被照亮，出现沿着曲面的亮纹。

5. Moment Shadow Mapping

接下来我们简单介绍一个新的算法，Moment Shadow Mapping（MSM）。这种方法被设计出来是为了解决 VSSM 算法存在的漏光问题。我们可以将 light leaking 理解为：使用一阶矩和二阶矩对真实遮挡关系（或者说深度分布）的估计不够精确，因此 MSM 希望通过更高阶矩估计来改善分布拟合能力。

在 VSSM 算法中，我们对 blocker 分布的模拟更多是单峰近似，而现实中的深度分布往往包含多个遮挡层。换句话说，真实 shadow map 的深度分布更接近一个阶梯函数，而不是单一连续分布。理论上存在这样一个关系：前 阶矩，可以近似表示一个最多包含 个台阶的分布函数。

6.2 DFSS 的具体流程

DFSS 在渲染速率上显然是要更快的，但是 SDF 的计算和存储本身是非常贵的。一个优化是在生成 shadow map 之前，对静态 mesh 预先构建距离场函数 ，用于后续 shading 过程中快速查询 shading point 到最近表面的距离信息。加上这个预处理流程，我们总体步骤可以表述为：

  1. 预处理：生成 Mesh Distance Field
  2. Ray marching：从当前 shading point 出发，沿光线方向进行 SDF marching，每一步前进距离取当前位置的距离场函数值 ；
    满足 时，认为光线命中最近遮挡物，并记录得到遮挡物距离 ；
  3. 根据安全角估计当前点的可见度，利用该可见度调制直接光照强度，得到最终软阴影结果。
